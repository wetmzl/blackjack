# 玩法与叙事设计

本文记录当前已经实现并需要长期保持的产品规则。类型、Schema 与测试仍是可执行的最终事实来源。

## 产品定位

《House of Chances》是 Android 竖屏优先的单机 PWA，以黑杰克、累积式俄罗斯轮盘、技能卡和角色叙事组成一局可恢复、可复现的死亡牌局。当前不包含登录、联机、云同步、排行榜、PvP、商业化或运行时生成式对白。

应用包含三个顶层场景：

- `lobby`：玩法说明、角色选择、技能与天赋目录、设置与对局入口。
- `match`：牌桌、结果确认和对局总结；`execution-room` 仅作为未来表现层扩展位保留。
- `trophy-room`：按首次击败时间陈列的独特战利品；页首入口可进入独立的本地对局记录。

进行中的对局不得直接返回大厅。正常结束或主动中止都必须经过 `match-summary`，由玩家确认后才清除活动对局并写入历史。

## 叙事与术语

玩家是来自高位面的“策展人”，向泰拉发出邀请。回应邀请的“与会者”带着自己的执念进入古堡并参加“黑杰克轮盘赌”。公开规则下，与会者赢得整局可要求策展人实现一个愿望；隐藏规则下，策展人能够回溯失败时间线，直到保留与会者死亡的结果。

- `player` / `PLAYER`：策展人。
- `opponent` / `AI`：与会者。
- `staff`：发牌员；共享左轮图层只用于瞄准受罚的与会者。
- `player-killed`：兼容性领域标识；叙事上是策展人朝天花板击发并输掉当前时间线，不是策展人死亡。
- `opponent-killed`：发牌员实弹击发，与会者死亡。
- `escaped`：策展人主动中止牌局。
- `unconscious`、`defeated`、`trophy`：兼容性资源名；新叙事按死亡、遗体和收藏记录解释。

与会者的档案和对白不得知道或暗示策展人的时间回溯能力。旧“博士熟人牌局”或“假面舞会余兴”的设定不得继续扩写。

## 黑杰克变体

- 不存在 Split 和 Double Down；可用基础行动只有 Hit 与 Stand。
- 每轮双方各发两张牌：第一张公开，第二张私有。牌的拥有者能看见自己的所有牌，对方只能看见公开牌。
- 与会者每轮先手。Stand 在本轮永久生效；一方 Stand 后，另一方可连续行动直至主动 Stand 或爆牌。
- 每轮开局时双方的基础爆牌上限重置为 21；只在本轮生效的技能加成不会带入下一轮。
- Hit 得到一张私有牌。点数超过当前生效的爆牌上限时立即爆牌；达到 21 点不会自动 Stand，双方仍按各自决策继续行动。
- Blackjack 只指初始两张牌恰好 21 点。后续多张牌组成的 21 点不是 Blackjack。
- 双方初始 Blackjack 为平局；单方 Blackjack 立即获胜。普通败者装填 1 发，Blackjack 败者装填 2 发。
- 平局不装填、不扣扳机，但会为策展人增加 1 次抽卡次数。
- 整局共用一副 52 张标准牌。下一轮开始前剩余少于 12 张时重洗；不在轮中重洗。
- 牌桌轮盘状态下方显示“牌库　next：[牌]　i”状态栏；`牌库` 左对齐，next 代表下一张将从实体牌堆抽出的牌，只展示策展人当前掌握的牌面情报。“偷梁换柱”将策展人手牌塞回牌库顶后，该牌的点数与花色保持已知。状态栏的信息按钮说明牌堆总大小、next 含义与常规洗牌时机。

每次轮次结算都先翻开私有牌并等待玩家确认。平局确认后进入下一轮；产生败者时，确认后进入轮盘阶段。

## 俄罗斯轮盘

双方各有一把容量为 6 的左轮，只记录子弹数量，不模拟弹巢位置。装填数不超过容量，空枪后子弹不会清空，因此风险在整局中累积。

没有哑火修正时，扣扳机命中概率为：

```text
bullets / capacity
```

存在哑火概率时，最终死亡率为：

```text
(bullets / capacity) × (1 - misfireChance)
```

因此哑火只会发生在原本抽中实弹的区间，实际哑火概率为 `(bullets / capacity) × misfireChance`；自然空膛概率仍为 `1 - bullets / capacity`。

策展人受罚时，先进入 `roulette-reaction`，可使用该窗口合法的技能，再主动扣扳机。与会者受罚时不使用技能，策展人确认“静观好戏”后由发牌员扣扳机。翻牌后的中央通知按爆牌、点数比较、平局或 Blackjack 概括胜负、实际装填量及是否接受左轮惩罚；可确定的扳机取消效果显示为免于左轮惩罚。进入上述心跳等待窗口时，界面应立即预览并提示当前哑火概率；实际能力结算仍在 `before-trigger-pull` 完成，再由同一次轮盘随机数产生 `fired`、`misfire` 或 `empty-chamber`。轮盘瞬时结果只显示“咔哒……空膛”“咔哒……哑火！”或“砰！”。能力导致的哑火与自然空膛使用各自音效，但角色对白统一复用原有的“手枪未激发”状态池，不要求为技能哑火追加专用台词。无论空膛、哑火或命中，结果都需玩家确认后才进入下一轮或总结页。

## 技能抽取与库存

技能获取统一使用可累积的“抽卡次数”。策展人以 Blackjack 获胜时增加 2 次，普通胜利、失败或平局增加 1 次；对手以 Blackjack 获胜仍按策展人失败计，只增加 1 次。开局不再自动发放技能卡，也不阻塞发牌。天赋“早有准备”在对局创建时额外增加 1 次抽卡次数。

轮到策展人行动时，可以点击牌桌底部的“抽取技能”按钮。每次抽取固定生成 3 张候选，点击其中一张便立即获得该技能并消费 1 次抽卡次数，没有多选、二次确认或放弃步骤。弹窗打开期间不能执行 Hit、Stand 或主动技能；选牌后回到同一次行动决策。技能牌库已满时按钮不可用，尚未消费的抽卡次数保留。

候选来自全部已解锁且 `drop.enabled` 的 Player Skill，而不是大厅预装列表。同一次抽取按修正后权重无放回抽取，因此不会出现重复 Definition；主动技能已经持有时仍可再次候选，不可叠加的被动技能持有后排除。能力的 `primaryDomain` 只允许四个基础领域：赌徒（`gambler`）、老千（`cheater`）、情报官（`intelligence-officer`）、枪手（`gunslinger`）；skill offer 显示其中文名。Player Skill 另以 `skillTags` 声明抽取亲和，数组第一项必须等于 `primaryDomain`，后续项为次要流派；玩家可选择至多两个流派，匹配任一所选流派的技能权重统一乘 4（多标签不会重复乘）。活动能力 modifier 也只按 `skillTags` 匹配并继续依次累乘，开放 `tags` 不参与流派概率空间。

策展人的局内技能牌库最多保存 10 个真实 `SkillCardInstance`，主动和被动统一占位。主动技能可有多个独立实例并分别消耗；被动 Player Skill 与被动 AI Skill 必须声明有限 `ttl`，可按完整回合或成功触发次数计数。条件未命中、解析失败不扣触发次数；归零后不再发动，玩家被动牌同时离开牌库并释放槽位。被动默认不可重复，未来允许叠加必须由 Definition 声明。Talent 属于局外成长，不使用局内 TTL。

初始技能池包含情报官的“猎手直觉”“临界判断”“态势研判”和枪手的“实弹加注”“预付保费”“红心猎手”。老千主动技能“顺手牵羊”也属于初始池：玩家回合中将对手最后一张实体手牌直接移入自己的手牌，保留原卡 ID 与 `source: shoe`，不会复制或生成衍生牌；若目标最后一张牌是衍生牌则不可使用。“狂欢节”不属于初始技能，首次击败拉普兰德后解锁；首次击败霍尔海雅后解锁“羽蛇的记忆”，使用时获得一张与最后一张手牌点数、花色相同的衍生牌；首次击败白金后解锁玩家被动技能“天马视域”，每张持续5轮且可以叠加：对手零 Hit 后 Stand 时，每张仍生效的技能提供1点可跨轮累加的点数优势，对手一旦 Hit 便清空所有仅由“天马视域”产生的优势。“猎手直觉”替代旧版行动建议：获得后仅在当前回合持续公开下一张实体牌的花色；另两张情报牌只发布爆牌与点数高低结论。枪手的装填替换先于额外装填结算，因此“红心猎手”与“实弹加注”组合时按“最终红心数 + 加注数”装填。

## 能力与角色

Player Skill、AI Skill 与 Talent 是三个独立内容领域，Definition ID 不得跨域共享；它们只复用声明式执行底座。定义分别位于 `src/content/abilities/player-skills/`、`ai-skills/` 和 `talents/`，AI Skill 通过角色 JSON 的 `aiSkills` 绑定。每个 Definition 都必须声明一个四选一的 `primaryDomain` 与开放式 `tags`；Player Skill 还必须声明至少一个唯一 `skillTags` 流派，首项与 `primaryDomain` 一致。Talent 的解锁由数据定义（当前“早有准备”为击败 1 名角色），从 `defeats` 事实集合推导，不在 profile 中重复保存。

能力只能组合已注册的触发器、条件、选择器、效果和状态。新增内容不得通过角色 ID、能力 ID 或任意脚本回调绕过通用规则。

主动或被动 Player Skill、AI Skill 实际触发时，以独立的技能通知气泡显示发动者、技能名和效果；玩家与 AI 使用不同色调，多条通知按最新在上堆叠，每条显示 2.5 秒后渐隐移除。天赋与 `notify:false` 的内部规则不进入气泡。被状态封锁的主动技能牌保留禁用视觉与无障碍状态，但仍可点击以短暂提示“技能被禁用”；没有技能牌、窗口不合法或自身条件不满足时仍使用普通禁用行为。

角色机制需要持续公开变量、花色或牌时，可由角色 JSON 声明一个与会者专属信息栏。它固定显示在牌库状态栏下方，并可打开角色专属解释；一个角色只占用一个信息槽，具体值由通用能力底座从当前牌局投影，不在 UI 或核心 reducer 写角色特判。

角色目录负责大厅和历史记录所需的轻量元数据；完整档案、AI、对白、机制和牌桌资源按需加载。角色的详细接入与美术规格见 [新增与会者工作流](adding-a-character.md)。

角色目录支持多个自定义 tag，tier 同时作为 `tier:s`、`tier:a` 等标签参与查询。当前解锁路径为：初始仅可邀请翎羽；击败任意角色后开放艾丽妮、白金、拉普兰德和 W；击败任意 S 级角色后开放霍尔海雅和年；击败拉普兰德后开放德克萨斯；累计击败 3 名不同角色后开放刺玫。上述条件均由角色目录声明并由首次击败记录驱动，不在核心逻辑中写角色特判。对决入口从仍存活且已解锁的角色中随机展示最多三名候场宾客。每名已击败宾客只写入一次独立的首次击败记录；对决入口下方的已击败名册按首次击败时间倒序、每批三名懒加载，已击败宾客仍可从档案再次邀请。

## AI 与信息权限

AI 的阈值策略和对白系统互相独立。AI 只接收 `buildObservation(state, "opponent")` 生成的视图，不能读取策展人的私有牌、牌堆顺序、未来随机数或技能窥视信息。

每名与会者在角色 JSON 中配置 `P/A/B/C`，默认分别为 `0/1/1/1`。建局时生成整局不变的 `Rmatch`，每手开始时生成新的 `Rplay`；两者范围均为 `[-0.3, 0.3]`。令 `Bp` 为策展人的子弹数，`Ba` 为与会者的子弹数：

```text
T = 16 + P + 0.1 × A × (Bp - Ba) + B × Rmatch + C × Rplay
```

与会者手牌总点数小于等于 `T` 时 Hit，否则 Stand。`Bp - Ba` 为正表示与会者处于子弹优势，阈值随之升高，使其更倾向冒险。两个噪声及 AI 随机流快照都保存在领域状态中；一次手牌内的重复决策不重新抽噪声。

对白根据当前有限状态解析到唯一对白池。新增对白变体不得改变发牌、AI、轮盘、掉落或能力的随机结果。

## 存档与收藏

- 重要领域行动后自动保存运行时档；刷新、关闭浏览器或重启设备后应恢复未完成牌局。
- 运行时档只保存牌局状态机、领域状态和随机流，不保存 DOM、动画进度、粒子或临时 Modal 状态。
- 长期档独立保存 profile、设置、对局记录、首次击败与解锁依据，并包含布尔字段 `skipTutorial`，表示后续是否无需再显示新手引导。
- 两类存档各自使用严格 Zod Schema 与独立版本。运行时档不兼容时，经玩家一次确认后只舍弃未完成牌局；长期档发生破坏性变更时必须提供逐版本迁移，启动阻塞页同时提供删除、迁移和导出原件，导入失败时也提示迁移能力或明确没有迁移路径。
- 默认导出与导入只处理长期档，不携带或覆盖未完成牌局。
- 完成并确认的对局压缩为历史记录，包含最终弹量、爆牌次数和 Blackjack 次数。
- 首次击败记录与对局历史分别持久化：前者驱动战利品、已击败名册、角色解锁和技能解锁，后者只驱动可查看的逐局统计。
- 清理对局历史不会删除首次击败记录、战利品、角色/技能解锁、累计局数或胜场。
- 战利品陈列室每名角色只显示一件藏品，日期固定为首次击败时间；再次获胜不会改写它。等级标签与边框按 B 蓝、A 紫、S 金、SS 红显示。
- 只有策展人获胜、与会者死亡且角色配置了 `trophyGallery` 时，才产生可进入的头肩档案、竖屏全身记录与局部观察点。落败或中止对局不得泄露这些资源。
- 全屏鉴赏固定以一张共享工业陈列舱作为底图，再叠加角色的透明全身层；角色可通过数据声明按“正面 → 左侧 → 俯卧 → 右侧”循环的其他陈列姿势。玩家可在陈列舱范围内左右滑动，或点按舱体两侧箭头翻转人物层；默认姿势的局部观察点不会错误显示在其他姿势上。
- 全屏鉴赏右侧提供可收放的纸质人物档案：收起时只露出边缘标签，展开后与陈列舱等高。椅子遗体图、六项身份记录和尸体状况均由角色 JSON 提供；UI 不根据角色 ID 推断或补写档案内容。

## 视觉与交互

- 优先检查 390×844 与 320×720 竖屏尺寸，处理安全区、拇指操作、文本可读性和弹窗返回链路。
- 角色是牌桌后的视觉主体，牌、弹量与操作区保持清晰；不依赖 hover、右键或小型 PC 控件。
- 牌桌中央通知区左侧固定显示红色的当前行动者爆牌上限；技能发动情况在牌桌上方独立气泡堆叠展示，不遮挡整屏。
- 角色、桌面、背景使用一致的日式二次元游戏语言。表情、眼睛和关键动作在手机尺寸下必须可辨。
- 扑克牌由 DOM/CSS 组合 rank、suit 与 frame，避免图像模型生成错误牌面。衍生牌只用双线异色边框区分，不显示角标；多萝西的共振牌复用菱形角标，暗牌也显示该标记但不额外揭示点数。
- 技能抽屉按真实卡牌实例固定两列、最多五行，并随 1–10 张牌动态增高；底板保持半透明。被动技能以占位卡展示，但不伪装成可发动按钮。
- 动画、音效和震动负责表现节奏，但不得改变领域状态。启用动态效果时，每次点击可用按钮会先触发 8ms 的极轻震动；确认、空枪和枪响仍可用更强的专属反馈覆盖它。流派选择与取消使用空枪强度，战利品人物翻动使用总长 400ms 的低占空比反馈。抽取技能与使用玩家主动技能分别走可替换的独立音效 cue，当前都临时复用 Stand 音效；枪响 1.5s 后播放死亡余韵，战利品人物翻动、流派选择与取消也使用各自的 Ogg cue。减少动态效果设置必须受到尊重。
